# workbench-home Specification

## Purpose

工作台首页与导航信息架构：首页聚焦 WeLink 与 CodeHub 两个业务域的动态汇总
（数据管理仅为 CRUD 演示域、环境检测为系统工具，均不上首页），侧栏按分组组织，
同时守护「既有域功能与路由不被首页改造破坏」的边界。

## Requirements

### Requirement: 首页业务域面板聚合

工作台首页 SHALL 聚焦展示两个业务域的状态面板——WeLink 助手（含快速建群指标
与入口）与 CodeHub 检视；每个面板包含域名称、一句摘要、关键指标（数字/状态）
并可点击跳转到对应页面。数据管理（CRUD 演示域）与环境检测（系统工具）MUST NOT
出现在首页的任何信息块中，其入口仅保留在侧栏导航。

#### Scenario: 首页展示双域面板

- **WHEN** 用户进入工作台首页
- **THEN** 页面呈现 WeLink 与 CodeHub 两个业务域面板，每个面板带有摘要与关键指标
- **AND** 页面不出现数据管理、环境检测相关的任何信息

#### Scenario: 面板跳转到对应域

- **WHEN** 用户点击某个业务域面板（或面板内入口）
- **THEN** 应用导航到该域对应的页面（WeLink 助手 / 快速建群 / CodeHub 检视）

### Requirement: 侧栏导航分组

侧栏导航 SHALL 按路由元信息声明的分组渲染（工作台 / WeLink / CodeHub / 系统），
组内顺序沿用路由表既有排序规则；未声明分组的带图标路由 MUST 仍出现在侧栏
（归入默认分组），不得因引入分组而静默丢失。

#### Scenario: 分组渲染

- **WHEN** 用户查看侧栏
- **THEN** 导航项按分组标题归置展示，组内顺序与路由表声明一致

#### Scenario: 未分组路由不丢失

- **WHEN** 某带图标路由未声明分组
- **THEN** 该路由仍出现在侧栏默认分组中

### Requirement: 既有域不被首页改造破坏

首页与导航改造 MUST NOT 改变既有页面（数据管理、WeLink 助手、快速建群、配置、
环境检测、关于）的路由路径与功能行为。

#### Scenario: 既有路由保持可达

- **WHEN** 首页改造合入后用户访问任一既有页面路径
- **THEN** 页面正常渲染且功能与改造前一致

### Requirement: 浏览器模式信息架构一致

浏览器（web Bridge）模式 SHALL 呈现与桌面模式一致的工作台首页信息架构（卡片与
分组），两者差异仅允许体现在摘要数据来源上。

#### Scenario: web 模式渲染首页

- **WHEN** 用户在浏览器开发模式打开工作台首页
- **THEN** 域卡片与导航分组正常渲染，页面无报错
