# codehub-review Specification

## Purpose
CodeHub MR 检视信息域：经内网 codehub-cli 工具拉取 MR 合并与检视信息，快照落库、
离线可查、全程只读——内网环境下对标「gh CLI 之于 GitHub」的接入方式。

## Requirements

### Requirement: 连接配置由用户提供

系统 SHALL 提供连接配置：codehub-cli 可执行文件路径与访问 token 均由用户在配置页
显式填写并保存；配置不完整时，检视域 MUST 呈现「未配置」引导态（含填写指引），
而非报错或空指针式崩溃。

#### Scenario: 未配置引导态

- **WHEN** 用户未配置 codehub-cli 路径或 token 即进入检视页
- **THEN** 页面展示未配置引导态与配置入口，不发起任何 CLI 调用

#### Scenario: 配置保存后可验证连通

- **WHEN** 用户保存连接配置后触发连通性验证
- **THEN** 系统调用 codehub-cli 自检能力并明确反馈可用或不可用及原因

### Requirement: token 全链路脱敏

访问 token MUST NOT 以明文出现在任何日志输出中；调用子进程时的传参方式由实现
决定，但日志侧 MUST 对 token 值做遮蔽。

#### Scenario: 日志不泄露 token

- **WHEN** 同步或连通性验证过程产生日志（含失败诊断日志）
- **THEN** 日志内容中不出现 token 明文

### Requirement: CLI 通道走既有闸门语义

codehub-cli 调用 SHALL 复用通用子进程通道的既有安全语义：仅白名单内程序可执行、
参数以数组传递不经 shell、具备超时预算与 UTF-8→GBK 编码兜底；CLI 自身的非零退出
按业务结果返回，仅「未放行 / 进程无法启动 / 超时强杀」属通道故障。

#### Scenario: 白名单外程序被拒绝

- **WHEN** 连接配置中的可执行文件不在宿主白名单内
- **THEN** 调用被拒绝且不启动任何子进程，界面给出明确原因

#### Scenario: GBK 输出可读

- **WHEN** codehub-cli 输出 GBK 编码的中文字节序列
- **THEN** 解析侧获得正确可读的中文文本

#### Scenario: CLI 超时归类为可重试故障

- **WHEN** codehub-cli 单次调用超出超时预算被强杀
- **THEN** 该轮同步按可重试的通道故障处理，已有快照不受影响

### Requirement: 同步管线与退避

系统 SHALL 支持手动刷新与周期轮询两种同步方式（间隔由用户配置）；同步按 MR 唯一
标识以覆盖写方式更新本地快照；同步失败 MUST 按退避策略重试且不阻塞 UI；单轮失败
MUST NOT 破坏既有快照数据。

#### Scenario: 手动刷新更新快照

- **WHEN** 用户点击手动刷新
- **THEN** 系统执行一轮同步并更新快照与「最后同步时间」

#### Scenario: 轮询间隔生效

- **WHEN** 用户配置了轮询间隔并开启自动同步
- **THEN** 系统按该间隔周期执行同步

#### Scenario: 自动同步不依赖进入检视页

- **WHEN** 用户已开启自动同步但停留在其他页面（或从未打开检视页）
- **THEN** 应用启动时即按配置的间隔调度同步；配置页保存后立即按新配置重新调度

#### Scenario: 同步失败退避且旧快照可读

- **WHEN** 连续同步失败（CLI 不存在 / 超时 / 输出不可解析）
- **THEN** 系统按退避策略推迟重试，检视页仍完整展示最后一次成功的快照

#### Scenario: 输出截断时标注快照可能不完整

- **WHEN** 单次 CLI 调用的输出触到宿主截断上限，本轮仅部分 MR 记录被抢救入库
- **THEN** 已解析的记录照常落库（同步不判为失败），且该仓库被记入本轮降级清单，
  检视页状态条展示「数据可能不完整」提示；未被截断的正常轮次不展示该提示

### Requirement: 快照落库与离线只读降级

MR 数据 SHALL 落 SQLite 快照（随同步覆盖更新，不留存历史版本，数据量有界）；
远端已消失的 MR 本期不做按轮差集清理，快照保留其最后已知状态，清理只随仓库删除
发生；CLI 不可用或无法联网验证时，检视页 MUST 展示最后成功快照并标注其同步时间；
从未同步成功时展示空态。

#### Scenario: 离线展示最后快照

- **WHEN** codehub-cli 不可用时用户打开检视页
- **THEN** 页面展示最后一次成功的快照数据及对应同步时间，并标识「非实时」

#### Scenario: 从未同步的空态

- **WHEN** 从未有过一次成功同步且 CLI 不可用
- **THEN** 页面展示空态与重试指引

### Requirement: 检视页筛选与详情

检视页 SHALL 支持按仓库分组浏览、按状态筛选（开启 / 已合并 / 已关闭），
并可查看单条 MR 的详情（含检视意见摘要）。列表浏览只读本地快照，MUST NOT 在每次
浏览时触发子进程调用；唯一例外是按单条补拉：快照中该条详情缺失时，点开详情可发起
一次 `mr view` 并回填快照（同一条在飞期间去重，补拉失败不阻塞浏览、退回占位态）。
「待检视」的判定口径不在本期范围（见 proposal 不做清单）。

#### Scenario: 状态筛选

- **WHEN** 用户选择某一状态筛选
- **THEN** 列表仅展示该状态的 MR

#### Scenario: 查看详情

- **WHEN** 用户点击某条 MR
- **THEN** 展示该 MR 的详情与检视信息（数据来自本地快照）

#### Scenario: 快照缺详情时按条补拉

- **WHEN** 用户点开的 MR 在快照中没有详情载荷（同步输出截断或字段缺失）
- **THEN** 系统发起一次该条的详情补拉并回填快照；同一条重复点击不并行发起多次调用，
  补拉失败时面板显示「无详情载荷」占位且列表继续可读

#### Scenario: 浏览过程不产生批量调用

- **WHEN** 用户仅切换筛选、翻页或切换仓库
- **THEN** 不发起任何 CLI 调用（数据全部来自本地快照）

### Requirement: 只读边界

检视域 MUST NOT 触发任何对 CodeHub 的写操作（评论 / 批准 / 合并等），仅允许
拉取与查询类 CLI 调用。

#### Scenario: 无写操作

- **WHEN** 审计检视域全部 CLI 调用面
- **THEN** 不存在任何会产生写副作用的调用
