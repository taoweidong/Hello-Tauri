# windows-command-exec Specification

## Purpose

提供受控的 Windows 系统命令执行通道：只有登记过的命令才能执行，输出结构化取回、
编码可靠、超时可预算，为环境诊断与运维类后续功能提供安全底座。

## Requirements

### Requirement: 命令注册表闸门

系统 SHALL 只执行命令注册表中登记的命令项（每项含程序名、参数模板、用途说明、
超时预算）；对未登记命令的执行请求 MUST 被拒绝且不产生任何子进程。

#### Scenario: 执行已登记命令

- **WHEN** 调用方按注册表中的命令 ID 与参数发起执行
- **THEN** 系统启动对应子进程并返回执行结果

#### Scenario: 执行未登记命令

- **WHEN** 调用方请求的命令 ID 不在注册表中
- **THEN** 系统拒绝执行、返回明确的「命令未登记」错误，且未启动任何子进程

### Requirement: 执行结果结构

每次执行 SHALL 返回统一结构：退出码（强杀时为空）、stdout 文本、stderr 文本、
stdout/stderr 截断标志、超时标志与耗时（毫秒）。

#### Scenario: 命令正常完成

- **WHEN** 已登记命令执行结束且未超时
- **THEN** 返回结果包含真实退出码、两路输出文本、截断与超时标志均为否、耗时为正值

### Requirement: 退出码语义

退出码非 0 MUST NOT 被当作通道故障；仅「命令未登记」「程序未获宿主白名单放行」
「进程无法启动」三类属于通道故障并报错，命令自身的非零退出与错误输出按正常结果返回。

#### Scenario: 命令自身失败

- **WHEN** 已登记命令以非零退出码结束
- **THEN** 调用正常返回（不 reject），结果中退出码与 stderr 如实呈现

#### Scenario: 程序未获宿主放行

- **WHEN** 注册表项的程序不在宿主白名单内
- **THEN** 调用以通道故障报错结束

### Requirement: 输出编码兜底

命令输出 SHALL 先按 UTF-8 严格解码，失败时回退 GBK 解码，保证中文 Windows 环境
（控制台代码页 GBK）的输出可读且不丢字节。

#### Scenario: GBK 编码输出

- **WHEN** 命令输出为 GBK 编码的中文字节序列
- **THEN** 返回的 stdout 文本为正确可读的中文

### Requirement: 超时与输出截断

每条登记命令 MUST 受其超时预算约束：超时时强杀进程并返回超时标志；单路输出超过
上限时截断保留前段并置截断标志，进程 MUST NOT 因管道写满而永久阻塞。

#### Scenario: 命令超时

- **WHEN** 命令执行超过其登记的超时预算
- **THEN** 进程被强杀，返回结果超时标志为真、退出码为空，调用在预算后确定性地完成

#### Scenario: 输出洪泛

- **WHEN** 命令的单路输出超过上限（2 MB）
- **THEN** 返回结果保留上限内的前段输出且截断标志为真，命令正常结束

### Requirement: 参数按字面传递

命令与参数 MUST 以数组形式直接传给目标程序、不经任何 shell 解释；参数中的特殊
字符（引号、管道符、重定向符等）MUST 按字面处理。

#### Scenario: 参数包含 shell 特殊字符

- **WHEN** 登记命令的某个参数值包含 `&`、`|`、`>` 等 shell 元字符
- **THEN** 该值作为单个字面参数传给目标程序，不产生 shell 解释的附加行为
