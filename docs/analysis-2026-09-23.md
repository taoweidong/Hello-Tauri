## 四、问题清单（按严重度排序）

### P0-1 · 每页条数双真值，配置改动不生效

**位置**：`src/views/TableCrudView.vue:41-43`、`src/stores/table.ts:36`、`src/views/SettingsView.vue:81`

`pageSize` 同时存在于 `appStore.settings.pageSize`（配置）和 `tableStore.pageSize`（表格）两处，仅靠一次性同步：

```ts
// TableCrudView.vue  只在挂载时同步一次
onMounted(() => {
  tableStore.pageSize = appStore.settings.pageSize
})
```

**复现路径**：进入「数据管理」（此时 `onMounted` 已执行完，组件被 `keep-alive` 缓存）→ 切到「配置」把每页条数 10 改为 50 并保存 → 回到「数据管理」→ **分页仍为 10 条**。

反向也不通：在表格页用分页器下拉把条数改为 20，`tableStore.pageSize` 变了但 `appStore.settings.pageSize` 不变，因此「自动保存」不会落盘，重启后回到 10。

**根因**：`keep-alive` 使 `onMounted` 不再重跑，一次性同步失效；且分页器 `v-model:page-size` 直接绑定了 store 而非配置源。

**修法（推荐 A，符合「降低复杂度」）**：删除 `tableStore.pageSize`，让分页器直接绑定配置源，形成单一真值：

```vue
<el-pagination v-model:page-size="appStore.settings.pageSize" ... />
```

配合已有的 `autoSave` 深度 watch，改动会自动持久化，`onMounted` 那两行同步代码可直接删掉。**收益：少一份状态，顺带修掉两个方向的不同步。**

### P0-2 · `pack.bat` 成功路径重复 `popd`，失败路径弹出调用者目录

**位置**：`scripts/pack.bat:58` 与 `scripts/pack.bat:98`

成功路径已经 `popd` 一次后 `goto :end`，而 `:end` 标签下**又执行了一次 `popd`**：

```
echo [3/3] 打包完成，产物位于 release 目录
popd 2>nul            ← 第一次
set "RC=0"
goto :end
...
:end
popd 2>nul            ← 第二次（栈不平衡）
endlocal & exit /b %RC%
```

失败路径更麻烦：`pushd "%ROOT%"` 失败时跳到 `:err_root`，那里**从未成功 `pushd` 过**，却同样会走到 `:end` 执行 `popd` —— 这会把**调用者**压入的目录弹掉。

**实际影响**：双击运行时无外层 `pushd`，`popd` 静默失败（`2>nul` 吞掉了输出），所以问题不显形；但若有人在批处理里 `call pack.bat`，工作目录会被无声改变。

**修法**：用标志位守卫，只有成功 `pushd` 过才 `popd`：

```bat
set "PUSHED="
pushd "%ROOT%" 2>nul
if errorlevel 1 goto :err_root
set "PUSHED=1"
...
:end
if defined PUSHED popd 2>nul
```

并删除成功路径上第 58 行的提前 `popd`。

### P1-3 · Element Plus 全量引入，主 chunk 超 1 MB

**位置**：`src/main.ts:3-6`、`src/main.ts:13`

```ts
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
...
app.use(ElementPlus, { locale: zhCn })
```

全局注册使得**全部组件与全量样式**进入产物，实测：

| 产物 | 原始体积 | gzip |
| --- | --- | --- |
| `index-*.js` | **1,027.96 kB** | 332.64 kB |
| `index-*.css` | **365.54 kB** | 49.30 kB |

构建器已明确告警 `Some chunks are larger than 900 kB`。

**与需求的冲突**：需求原文要求「资源占用少」。exe 体积（3.25 MB）确实优秀，但解析 366 KB CSS 与 1 MB JS 会影响窗口首屏与冷启动表现。

**修法**：改用按需引入（`unplugin-vue-components` + `ElementPlusResolver`），仅打包实际用到的约 15 个组件。这是 Element Plus 官方推荐路径，且**不引入新的运行时依赖**（仅构建期插件），符合内网约束。

**注意**：切换后需确认 `element-plus/theme-chalk/dark/css-vars.css` 仍被加载（暗色主题依赖它），以及 `ElMessage` / `ElMessageBox` 这类**函数式组件**在按需模式下会被自动处理，但需实测验证。

### P1-4 · 零测试 / 零 lint / 零 CI

**现状**：`package.json` 的 `devDependencies` 中无 vitest、无 eslint、无 prettier；仓库无 `.github/`；`scripts` 中无 `test` 与 `lint` 命令。

**为什么这是高风险**：`src/stores/table.ts` 是本项目**唯一承载业务规则**的模块（筛选、分页、统计、ID 分配），却是纯函数式、零副作用的 —— 它是测试性价比最高的目标，目前完全没有保护。任何后续改动都只能靠手点验证。

**建议的最小可行基线**（按投入产出排序）：

| 优先级 | 目标 | 内容 |
| --- | --- | --- |
| 高 | `stores/table.ts` 单测 | `filtered` 关键字/分类组合、`pageCount` 除零边界、`remove` 后 `page` 回退、`nextId` 分配 |
| 中 | `web.ts` / `index.ts` 单测 | Bridge 双实现契约一致性；运行时探测分支 |
| 中 | ESLint + Prettier | 沿用 `tsconfig` 的 `strict` 基调 |
| 低 | GitHub Actions | `typecheck` + `build` + `test` 三连 |

> 这与 Superpowers 方法论「没有失败的测试，就不算实现」直接对齐。建议在下一轮改动中先补齐高优先级部分，再动 `stores/table.ts`。

### P1-5 · `web.ts` 硬编码版本号，存在漂移风险

**位置**：`src/api/web.ts:17`

```ts
version: '0.1.0',
```

`package.json` 与 `tauri.conf.json` 的版本均为 `0.1.0`，三处手工维护。发版时若只改前两处，「关于」页在浏览器模式下会显示过期版本，误导排查。

**修法**：Vite 支持在构建期注入，避免运行时硬编码：

```ts
// vite.config.ts
define: { __APP_VERSION__: JSON.stringify(pkg.version) }
```

Rust 侧已通过 `app.package_info()` 动态取值（`commands.rs:54`），所以**只需修 web 分支**。

### P2-6 · `autoSave` 语义与「仅应用」按钮不一致

**位置**：`src/views/SettingsView.vue:92-95`、`src/views/SettingsView.vue:31-33`

开关文案是「自动保存 / 修改后立即写入本地」，但实际行为是：修改表单**不生效**，必须点「仅应用」或「保存配置」才把 `form` 写入 `appStore.settings`。

即 `autoSave` 控制的是**「应用之后是否落盘」**，而非**「修改之后是否立即生效」**。用户按字面理解会以为改完即生效。

**修法**（二选一）：
- 改文案为「应用后自动写入本地」，最小改动；
- 去掉 `form` 副本，让表单直接绑定 `appStore.settings`，真正做到改完即生效 —— 与 P0-1 的「单一真值」方向一致，可一并处理。

### P2-7 · `defaultRoute` 仅在冷启动首页生效

**位置**：`src/App.vue:15`

```ts
if (target && target !== '/' && route.path === '/') {
  void router.replace(target)
}
```

只在 `route.path === '/'` 时跳转。冷启动正常，但若 webview 保留了上次的 hash（非 `/`），配置的默认首页不会生效。属于边界行为，建议在文档中明确或放宽条件。

### P2-8 · `nextId()` 会复用已删除的 ID

**位置**：`src/stores/table.ts:67-69`

```ts
function nextId() {
  return rows.value.reduce((max, row) => Math.max(max, row.id), 0) + 1
}
```

取「当前最大 ID + 1」。删除最大 ID 那条记录后再新增，会**复用刚被删除的 ID**。在无外部引用的示例场景中不构成故障，但若后续接入后端，ID 复用会引发主键语义问题。建议改为单调递增计数器。
