### P1-1 两套平行图标系统（架构性冗余）

| 系统 | 位置 | 引用方 | 状态 |
| --- | --- | --- | --- |
| A | `src/components/icons.ts`（184 行，含 SHAPES 表 + 28 个 `IconXxx` 导出 + AppIcon） | 全部 5 个视图 + MainLayout | **活代码** |
| B | `src/components/icons/` 目录（`icon-paths.ts` 64 行 + `AppIcon.vue` 63 行） | **零引用**（grep 全库仅命中自身定义与注释） | **死代码** |

证据：`git grep -l "components/icons/"` 除目录内两文件自身外无任何命中；`git log` 显示目录随 `e2b0022` 提交，该提交工作日志明言产出物为 br_twd_ 分支的组件（AppLayout/GlobalSearch/UploadZone 等在本仓库不存在）。

根因：`e2b0022`（main 上的"UI 优化"提交）与 `614378d`（"build:exe"提交）实为 **br_twd_ 分支的工作被错误提交进 main**——两个提交的 stat 只含 3 个新文件，未触碰本仓库任何既有源码；其描述的组件（WelcomePage、TabBar、GlobalSearch）在 main 工作区不存在。build/web 里的 chunk（memory-store、tauri-adapter）与 `日志解析工具` 标题亦来自 br_twd_ 分支源码。

**处置**：删除 `src/components/icons/` 整目录（连同 `e2b0022` 的 `.impeccable.md` 误带产物一并评估，见 P2-2）。

### P1-3 双 cargo 配置冲突风险

| 文件 | 内容 | 状态 |
| --- | --- | --- |
| `.cargo/config.toml`（仓库根） | target-dir=target + crt-static | 活配置，README 与 Cargo.toml 注释均指向它 |
| `src-tauri/.cargo/config.toml` | 仅 crt-static（缺 target-dir） | **冗余且易误导**：来自误提交 |

**处置**：删除 `src-tauri/.cargo/config.toml`（保留根配置唯一真值）。

## 三、保留不改的项（说明理由）

| 项 | 理由 |
| --- | --- |
| `webBridge.readTable/writeTable`（P1 遗留 JSON 通道） | **非死代码**：`sqlRecordsBackend.prepare()` 用它做旧版 table.json → SQLite 升级迁移（P3 设计决策，records.spec.ts 有覆盖）；web 模式内存后端也用 localStorage 键值对齐该契约 |
| `webBridge.dbMigrate` 返回 `[]` 而非抛错 | 有意为之：web 模式 recordsBackend 走内存实现不会调它，契约完整性优先（类型签名要求返回 Promise<number[]>） |
| `br_twd_` 分支本身 | 含 11 万行独立项目（日志解析工具），与 main 是两个项目共用一个仓库；删分支需用户单独决策，本轮不动 |
| `Cargo.lock` | 二进制项目最佳实践，锁依赖 |
| Rust 侧 6 模块（commands/db/fs/logging/storage/main 共 800 行） | 全部被 `lib.rs` generate_handler 注册，无死命令 |

## 四、优化建议（本轮不做，供后续决策）

1. **`e2b0022`/`614378d` 的错误提交根因**：疑似在 main 上 checkout 了 br_twd_ 的工作文件（或 worktree 状态串线）。建议后续将 br_twd_ 项目拆到独立仓库，避免再误提交。可用 `git rm` 修正本轮已处理，但历史提交保留原样（重写历史风险大于收益）。
2. **`build/` 目录名**：br_twd_ 的 vite outDir 是 `build/web`，本仓库是 `dist`。同名不同义是本次误提交的诱因之一，若保留双项目共用仓库，建议 br_twd_ 改用 `dist-web` 之类命名。
3. **`verify.mjs` 的 `--escalated` 需求**：cargo 写 target/ 需无沙箱环境，属运行环境约束，无法代码层消除，保留现状。
4. **图标树摇**：icons.ts 为 28→23 个导出后，主 bundle 已按需打包（ESM 命名导出可被 tree-shake），无需 manualChunks。
